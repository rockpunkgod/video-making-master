# 第28节：滑块驱动三维文字旋转

[原课程](https://www.bilibili.com/video/BV1c7GTzMEh5/?p=28)，最终表达式15:51、关键帧与运动模糊15:50–16:30。课程核心是嵌套if/else和一维Z Rotation映射；原课已准备好的Illustrator矢量图、三维层和摄影机是前置素材，不能说教程展示了它们全部数值。

## 原式与边界

滑块位置取二维Null“控制”的Position X，Y固定225。保留课程严格条件：

```javascript
a=thisComp.layer("控制").transform.position[0];
max_s=300;
min_s=20;
if((a>min_s)&&(a<max_s))
    [linear(a,min_s,max_s,20,300),225];
else
    if(a>max_s)
        [max_s,225]
    else
        [min_s,225]
```

三维文字层Z Rotation为`linear(a,20,300,90,-90)`，各属性都独立定义a和范围。不能把它改成2D旋转或先clamp滑块再用滑块输出控制文字。AE实际探针证实：a=300时原式滑块回20，文字仍为−90；a=300.01滑块回300。默认保留这个原课缺陷，`--repair-boundary`明确将后一个条件改为>=，只属于修复变体。

原课第一次键值在界面显示15.8/290.1，末键334.8/292.1；都是四舍五入显示值，原始小数未恢复。末键先为3:04，后来移近。最终10/12/25/28/29帧的X读数与末键41帧的线性插值相符，因此用41帧作为反算值，而非直接读出的关键帧时码。不自行加弹簧或缓动。原课启用运动模糊，快门未读到；本实现180°/−90°是自制参数。

## 可独立调用的当前范围

`scripts/build_rotation_slider.py --out 全新目录`生成请求，再调用同目录run_ae.py和render_ae.py。固定3秒、30fps、960×720，内部320×240。输入为六个ASCII字母/数字；`--labels PLANET`换字，`--fixture circles|hexagons|tags|stars`换自制矢量组件，`--end-frame 65`改变运动结束帧，范围12–80。每个组件的形状和文字、三维预合成、Null、摄影机、图层和表达式保留可编辑。

`--boundary-demo`额外生成自制测试时间轴：60→300，停在300，再至334.8；搭配`--repair-boundary`形成相同输入的修复对照。它不替代课程基线。默认3秒成片包含末键后的停留，画面出镜是同一旋转的结果，不额外循环回来。

当前自制图形替代原AI素材。为减少第一版空间偏差，使用已有SciPy和NumPy拟合18个原片可见圆心，得到examples/course-rotation-geometry.json中的等价相机、角点锚点与弧形布局；制作运行本身只需标准Python、FFmpeg和AE，不需要SciPy。拟合来自本实验，不是教程教授的步骤，也不是恢复的原始摄影机。source viewport约0.95比例及圆心测量有误差；不同字重、形状、运动模糊外观仍待视觉验收。

## 验证和失败诊断

tests/rotation-slider-results.json记录实际原生结果和剩余范围。原生检查含八个边界输入、90帧表达式、保存重开修改/恢复、三维camera/toComp投影；视频检查含全帧解码与滑块像素轨迹。模糊开关原生PNG另外比较边缘能量及亮度差，不能只凭开关值称生效。每帧全部字符的像素位置、原始字体/素材身份与精确快门不在已证明范围内。

二维Position返回维度与空间切线可能不一致；按本机属性value长度创建零切线，不硬写两个分量。重开工程后必须重新查找Comp/Layer，旧ExtendScript对象会失效。自制颜色曾与配置不符，已用明确if/else设色；以原生实际值和PNG为准，不能只读配置判断颜色正确。

审阅录像中的播放器时间、AE时间线及合成窗口时间码可能短暂不同步；跟随原片拖动的评审视频只是已渲染原生帧的重排，主成片和工程的两键动画不改变。不用它证明逐帧节奏相同。待反馈前保持candidate；输入图片、非Latin字符、任意组件数量、不同画幅/时长和新的摄影机布局均未建立通用适配。
