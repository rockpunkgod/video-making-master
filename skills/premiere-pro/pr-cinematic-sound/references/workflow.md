# 本机已验证接口与边界

原生通道：AE中的BridgeTalk.getTargets实际报告premierepro-26.0；向运行中的PR发送脚本并获得回执。CEP面板不可用不是PR脚本完全不可用。PR SDK通过项目路径检查后执行，原生journal防止重放。transport ACK不等于实际制作成功。

嵌套JSON字符串传递出现转义问题；现在将独立UTF-8 JSX读入消息body。原正则替换JSON序列化在此PR宿主产生无效反斜杠；已换成逐字符编码，并用引号、反斜杠、控制字符、中文和数组做真实PR回执验证。不要把无效JSON简单修饰成绿色报告；首版错误回执保留。

音量组件matchName为Internal Volume Stereo，级别在properties[1]。原生零dB读值0.17782793939114，参数减半时实际导出降低6.022dB，和预期6.0206dB相符。不得把归一化值直接当作dB；按本机实测unity×10^(dB/20)换算。

移动后音频关键帧以源时间为基准：已用起点1秒、源入点0的校准片，检查0/-6/-12dB分段的真实导出PCM。source_in非零尚未验证。overwriteClip会将插入点0.7秒变成0.708333秒；显式设置start/inPoint/outPoint/end可保留0.7和4.0995秒，须逐次读回。

八轨由安装内序列预设本地派生，不修改安装文件。AudioTracks数组每条记录就是一轨，额外添加“master记录”会得到九轨，已有原生失败取证。根据指定角色生成恰好八条后检查原生numTracks和实际轨道名。

包络为原生音量关键帧，插值类型0已由文档与本机执行核实。环境交叉淡化使用正弦/余弦等功率曲线采样；音乐闪避以明确对白窗口控制attack/release。原生工程保留所有输入及关键帧，音频源仍能独立替换。

原生exportAsMediaDirect返回No Error，不能硬编码期望0。导出的H.264/AAC相对独立参考延迟1024采样（21.333ms），未通过原定1ms门槛；相同序列PR WAV无延迟。现在FFmpeg只复制原生视频流，并从原生WAV编码AAC并封装，不使用数值参考作生产音轨。修正后基线对齐0采样、约-18.9LUFS、-4.36dBTP。

PR曾在RuntimeInstaller.DLL产生崩溃事件，另有多次进程消失但原因未确定。不得把每次退出都称为崩溃。冷启动工具只在无PR进程时显式打开指定实验工程；有实例时保留并让路径检查决定是否可执行。观察超时要检查同一进程/回执，不能盲目重启。当前仅验证短实验镜头，长片稳定性未验证。

听感：用户否决首版持续底噪；安静版获“底噪好转，但转场还需调”；suite001柔和录音转场版获“已自然，可以保留”。该认可只属于这个文件，未转移到suite002新输出。当前没有调用原生EQ、混响或Pitch Shifter接口；FFmpeg测试源不是这些PR效果器的验证。课程原法复刻仍缺，所有自制音量与几何场景仅作为泛化测试。

保存重开后，PR26零端点音量段的中间值发生变化，端点及时间读回仍正确，因此只查关键帧不足以保证实际声音。编译器对零端点段以不超过1ms间隔加密原线性幅度采样，并在保存关闭重开后才渲染。suite002三组真实音乐减半副本与原生WAV差异检查均超过56dB，原门槛35dB不变；失败历史保留于suite001。

首次导出可能包含Media pending占位图，isOffline=false和完整解码都不能排除它。suite002的第二组全300帧原素材对照失败，目视确认占位画面；已将失败导出与报告移入failed-media-pending-001，使用prepare_pr_sound_reexport.py从同一保存工程导出到清空后的生产文件名，随后重新检查。最终三组平均SSIM均超过0.99。出现该问题时先确认上次导出已终止、保存其证据，再等宿主完成媒体准备并从同一工程重导；不能盲目重放构建、重启活动进程或省略失败帧。
